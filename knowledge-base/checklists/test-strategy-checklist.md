## Validation Checklist

### Reference compliance

- [ ] The approved template was located and read.
- [ ] The example strategy was located and read.
- [ ] Sections 1 through 18 follow the template order.
- [ ] The level of detail is reasonably aligned with the example.
- [ ] Example-specific project data was not copied as fact.

### Evidence and accuracy

- [ ] Relevant project documents were searched recursively.
- [ ] Every project-specific claim is supported by a source or marked appropriately.
- [ ] No tools, owners, environments, URLs, targets, or dates were invented.
- [ ] Assumptions and recommendations are clearly labeled.
- [ ] Missing decisions appear in Open Questions and Gaps.
- [ ] Source Mapping identifies evidence for each major section.

### QA completeness

- [ ] In Scope and Out of Scope are explicit.
- [ ] Risks include impact, likelihood, and mitigation.
- [ ] Test types match project architecture and risks.
- [ ] Each selected test type includes objective, entry criteria, exit criteria, environment, owner, and considerations.
- [ ] Positive, negative, boundary, business rule, and error-handling coverage is addressed where applicable.
- [ ] Integration, data, security, privacy, performance, accessibility, compatibility, and UAT applicability were evaluated.
- [ ] Test data setup, teardown, privacy, and reset are addressed.
- [ ] Defect lifecycle, severity, priority, and triage are addressed.
- [ ] Suspension, resumption, and exit criteria are usable.

### Markdown quality

- [ ] The file is valid Markdown.
- [ ] Heading levels are consistent.
- [ ] Tables render correctly.
- [ ] No Word HTML, page numbers, or broken links remain.
- [ ] Repository-relative links are used when available.
- [ ] English grammar and terminology are consistent.
